# Переход со старого HTML-сайта на WordPress на Beget

## 1. Сохранить старый сайт

Сделайте резервную копию текущей директории сайта на Beget. Git-ветка `backup/static-before-wordpress-20261105` сохраняет код старой версии, но не заменяет резервную копию файлов, которые могли быть загружены прямо на хостинг.

Не направляйте автоматическое развёртывание `main` прямо в рабочую директорию старого HTML-сайта: у новой версии другой способ запуска.

## 2. Подготовить отдельный WordPress

В панели Beget создайте отдельную директорию сайта и тестовый адрес, установите WordPress. Выберите поддерживаемую версию PHP не ниже 8.2 и включите HTTPS. Учётная запись владельца создаётся при установке; пароли не кладите в GitHub.

Старый сайт продолжает работать, пока новая версия проверяется на тестовом адресе.

## 3. Перенести текущий локальный сайт — рекомендуемый вариант

Для точного совпадения с локальным сайтом перенесите его содержимое средствами миграции WordPress, совместимыми с исходной базой Studio и целевой MySQL/MariaDB. Нужны страницы, настройки, пользовательские шаблоны, макеты Embrace и медиатека. Простое копирование SQLite-файла Studio в MySQL не является переносом.

Архив миграции храните приватно: он может содержать пользователей, настройки и непубличные файлы. Не добавляйте его в публичный GitHub. Не переносите средства автоматического локального входа Studio на публичный сервер.

Установите/обновите тему `embrace` и плагины `embrace-tools`, `embrace-journal` из этого репозитория. Активируйте оба плагина и тему. Исправьте адреса исходного сайта средствами миграции с поддержкой сериализованных данных, затем пересохраните постоянные ссылки. Проверьте, что изображения загружаются с нового адреса.

## 4. Альтернатива — новое исходное наполнение

Этот вариант создаёт исходные страницы из комплекта, а не переносит все текущие изменения локальной базы.

После установки трёх ZIP-архивов активируйте тему и плагины. Если на хостинге настроен WP-CLI, из директории установленного WordPress выполните:

```sh
wp plugin activate embrace-tools embrace-journal
wp theme activate embrace
wp eval-file wp-content/plugins/embrace-tools/setup/seed.php
```

Скрипт импортирует комплект изображений и создаёт страницы. Он предназначен для первичного наполнения; не сбрасывайте `embrace_seed_version` для обновления уже отредактированного сайта. Для будущих обновлений достаточно заменить файлы темы/плагинов, сохранив базу и медиатеку.

Без WP-CLI используйте вариант миграции текущего сайта, а не открывайте `seed.php` в браузере.

## 5. Проверить перед переключением домена

- Главная, каталог, изображения и ссылки работают по HTTPS, без ссылок на localhost.
- Кнопка «Создать журнал» открывает редактор; фото, текст, четыре маркера, отмена и сохранение работают на телефоне.
- Проверены клавиатура iPhone и перемещение объектов внутри Telegram на реальном устройстве.
- Предпросмотр/PDF не содержат зону проколов.
- Макет владельца сохраняется после входа; посетитель не может менять исходные макеты и настройки.
- Сохранены существующие контакты, цены и содержимое юридических страниц.
- Есть резервная копия и возможность вернуть прежнюю директорию сайта.

## 6. Переключить рабочий домен

После проверки свяжите рабочий домен с новой директорией и корректно замените тестовый адрес в базе. Проверьте сертификат HTTPS и постоянные ссылки. Старый `index.html` не должен оставаться в корне нового WordPress: сервер может показывать его вместо `index.php`. Не удаляйте старую директорию до завершения проверки.

Ссылки старого сайта `privacy.html`, `terms.html`, `consent.html`, `seller.html` при необходимости перенаправьте на соответствующие страницы WordPress после проверки их адресов. Сохранённые в браузерах старые проекты могут потребовать ручного экспорта/импорта; совместимость со всеми старыми форматами не заявляется.
